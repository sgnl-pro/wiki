# Источники данных и обновление {#sources}

| Способ | Что подготовить | Как обновить |
|---|---|---|
| Ручной ввод | Поля и строки настроек карточки | Изменить значения и сохранить |
| Вставка из Excel | Строки в формате примера именно этой карточки | Вставить через кнопку в форме, проверить результат и сохранить |
| Импорт целого отчёта | XLSX, полученный экспортом отчёта DASHBOARD | При создании нового отчёта выбрать файл импорта |
| Привязка отчёта к Google Sheets или XLSX в DOCS | Полный шаблон карточки и отдельный именованный диапазон | На вкладке «Привязка» обновить карточку или весь отчёт |
| DOCS: замечания, согласования, SLA | Настроенные типы, роли, группы и фильтры | Обновить карточку, группу или отчёт |
| XLSX, MPP, СКУД, 1С, Техзор в настройках карточки | Файл или папка, предусмотренные её типом | Использовать импорт/обновление в настройках карточки; общая привязка отчёта не заменяет этот источник |
| 3D-модель | Обработанная модель, свойства и единицы измерения | Проверить источник и фильтры в просмотре; отдельно обновить значения и снимок превью |

## Три разных способа работы с Excel {#excel-modes}

**Вставка строк** заполняет табличную часть карточки. Нужный порядок столбцов и наличие заголовков смотрите в примере её формы. Вставка в карточке 42 добавляет строки, в 44 и 46 — заменяет существующую таблицу. Не переносите это правило на другие карточки без проверки их примера.

**Импорт отчёта** создаёт группы и карточки из структуры выгруженного DASHBOARD XLSX. Произвольная книга со строительными показателями не является шаблоном импорта целого отчёта. Для переноса сначала экспортируйте существующий отчёт, сохраните структуру и затем используйте импорт в окне создания нового отчёта.

**Привязка диапазона** читает полный блок карточки со служебными строками и данными. Самый надёжный образец — «Копировать данные карточки» на вкладке «Привязка».

| Строка полного блока | Содержимое |
|---|---|
| 1 | Заголовок карточки и его значение |
| 2 | Статус и значение `TRUE` или `FALSE` |
| 3 | Строка URL изображения |
| 4 | Тип карточки и его служебное значение |
| 5 | Разделительная строка |
| С 6-й | Данные в формате конкретного типа |

> Синхронизация переносит также заголовок и статус карточки. Служебный тип должен совпадать с типом карточки. Не удаляйте и не переставляйте служебные строки; не заменяйте значение типа его русским названием.

## XLSX из DOCS {#xlsx}

Порядок подключения описан в [настройках](/dash/settings#xlsx). Дополнительные требования:

- Используйте `.xlsx` размером не более **20 МиБ (20 × 1024 × 1024 байт)** для привязки отчёта. Это ограничение не следует автоматически применять ко всем другим загрузкам модуля.
- Диапазон должен быть именованным и ссылаться на область одного листа, например `'Отчёт'!$A$1:$D$20`. Допускаются ссылки на столбцы `A:D` или строки `1:20`; для них чтение ограничивается используемой областью листа.
- Используйте обычную ссылку на ячейки. Имена, заданные через формулы вроде `OFFSET(...)`/`СМЕЩ(...)`, и повреждённые ссылки `#REF!` не поддерживаются. Для предсказуемого результата создавайте отдельные прямоугольные диапазоны и уникальные имена во всей книге.
- DASHBOARD читает сохранённые в книге значения. Формулы самой книги пересчитайте и сохраните в Excel или онлайн-редакторе перед обновлением карточки.
- Для чтения файла необходим доступ к нему в DOCS. Удаление файла, ошибка скачивания и неверный диапазон — разные причины ошибки.

### Новая версия и частичное обновление {#xlsx-update}

1. Сохраните изменения как новую версию **того же файла** в DOCS. Если загружен другой файл, выберите его заново; одинаковое имя файла не сохраняет привязку.
2. После изменения списка диапазонов обновите их список. Сверьте диапазоны карточек.
3. Нажмите синхронизацию нужной карточки или всего отчёта. При чтении система проверяет текущую версию выбранного файла.
4. При массовой синхронизации проверьте число успешно и неуспешно обновлённых карточек. Успешные карточки уже сохранены; единого отката всего отчёта при ошибке одной карточки нет.
5. Ошибочную карточку обновите отдельно, прочитайте сообщение, исправьте файл или диапазон и повторите обновление. Прочие успешные карточки повторно обновлять необязательно.

Одновременно привязать отчёт и к Google Sheets, и к XLSX из DOCS нельзя. Смена источника сбрасывает прежнюю связь и диапазоны; предварительно сохраните экспорт и запишите настройки. Сама смена источника не заменяет последующую синхронизацию данных.

## Google Таблицы {#google}

Используйте ссылку вида `https://docs.google.com/spreadsheets/d/ИДЕНТИФИКАТОР/edit` и [пошаговую настройку](/dash/settings#google). Для чтения этой привязкой таблица должна быть доступна Google Sheets API без индивидуального входа пользователя Google: настройка чтения по ссылке должна соответствовать правилам вашей организации. Вход в SIGNAL не даёт права на закрытую Google Таблицу.

Если открывать таблицу по ссылке без индивидуальной авторизации нельзя, используйте XLSX в DOCS. При ошибке доступа проверьте ссылку, настройки общего доступа, доступность Google в сети и загрузку Google API в браузере. После восстановления доступа обновите список диапазонов, назначьте диапазон карточке и повторите синхронизацию. Чтобы заменить адрес, сначала отвяжите прежнюю таблицу. Не считайте размещение таблицы в Google и её публикацию в интернете одним действием.

## Что именно обновляется {#refresh}

| Действие | Результат |
|---|---|
| Сохранение полей карточки | Записывает её данные и настройки |
| Синхронизация на вкладке «Привязка» | Читает назначенный диапазон и записывает данные карточки |
| Кнопка обновления карточки/группы/отчёта | Запускает поддерживаемое её типом обновление из источника; не означает обновление любого внешнего сайта |
| «Обновить данные» в «Онлайн», «Мой отчёт», «Отчёт компании» | Обновляет данные превью соответствующего отчёта, рядом показывается дата обновления |
| Временное изменение фильтра просмотра | Меняет текущую выборку; само по себе не сохраняет настройки карточки |
| «Сохранить фильтры» в 50/51 | Сохраняет набор подрядчиков, работ и дат для последующих открытий |
| «Снимок для превью» | Сохраняет изображение 3D; отдельно от числовых значений и фильтров |

Автоматическое обновление онлайн-, личного и корпоративного отчётов запускается при открытии, когда последнее обновление было до начала текущего дня. Это не непрерывное фоновое чтение источника. Если нужна более свежая информация, используйте кнопку обновления. Развёрнутый просмотр некоторых карточек запрашивает данные отдельно от сохранённого превью: при расхождении сначала сравните источники, даты и фильтры.

# Форматы интеграционных файлов {#file-formats}

Примеры ниже обезличены. Это форматы, которые читает DASHBOARD, а не обещание совместимости с любой стандартной выгрузкой внешней системы. Сохраните блок как UTF-8 JSON и загрузите его в DOCS. Имена полей сохраняйте точно, числовые значения пишите без кавычек.

## СКУД: карточка 14 {#skud}

```json
[
  {"contractor":"Подрядчик А","employeeCount":12,"date":"01.11.2026"},
  {"contractor":"Подрядчик Б","employeeCount":8,"date":"01.11.2026"},
  {"contractor":"Подрядчик А","employeeCount":15,"date":"02.11.2026"}
]
```

Корень — массив. Для каждой строки обязательны `contractor`, `employeeCount`, `date`. Дата — `ДД.ММ.ГГГГ`, численность — неотрицательное число. Дополнительные разрезы `byPassReason` и `byRegistryStatus` не заменяют `employeeCount`.

При выборе всех подрядчиков факт за 01.11 составит 20; при выборе только А — 12. Обновление учитывает версии выбранного файла; более свежая запись того же подрядчика за ту же дату заменяет прежнюю. План для совпавших дат сохраняется. Старые импортированные строки, исчезнувшие из результата нового импорта, не сохраняются как ручные строки. Неверные строки пропускаются с предупреждением: проверьте результат, даже если часть данных загрузилась.

## 1С: карточка 22 {#onec}

```json
[
  {"docDate":"2026-11-01","partnerName":"Подрядчик А","docSum":100000,"docType":"Оплата"},
  {"docDate":"2026-11-15","partnerName":"Подрядчик А","docSum":50000,"docType":"Оплата"}
]
```

Выберите папку DOCS с файлами `.json` или `.txt`, содержащими JSON-массивы этого вида. `docDate` — дата документа, `partnerName` — контрагент, `docSum` — сумма, `docType` — тип документа для фильтра. Используйте даты ISO `ГГГГ-ММ-ДД`. В примере факт за ноябрь — 150000.

Данные суммируются по месяцу после фильтрации по контрагентам и типам документов. Не храните в выбранной папке несколько файлов с дублирующимися документами: суммы будут учтены повторно. Повторный импорт заменяет импортированный факт и сохраняет план совпавшего месяца; ручные строки других месяцев сохраняются. Для `.txt` требуется тот же JSON, а не произвольный текст или CSV.

## Техзор: карточка 93 {#tehzor}

```json
[
  {
    "objectId":"object-a","objectName":"Корпус А","updatedAt":"2026-11-01T12:00:00Z",
    "statistics":[
      {"contractorId":"contractor-a","contractorName":"Подрядчик А",
       "waiting":3,"verification":1,"handling":2,"fixed":4,"closed":10}
    ]
  }
]
```

Корень — массив снимков объектов. Обязательны строковые `objectId`, `objectName`, `updatedAt` и массив `statistics`. У подрядчика обязательны строковые `contractorId`, `contractorName` и **все пять числовых счётчиков**: `waiting`, `verification`, `handling`, `fixed`, `closed`. Отсутствующие количества записывайте как `0`. Используйте корректную дату-время ISO.

Выберите нужные объекты; пустой выбор объектов не означает выбор всех. Пустой выбор подрядчиков включает всех подрядчиков выбранных объектов. Карточка читает доступные версии файла; для одного объекта и даты приоритет у более свежей версии. Значения выбранных объектов за дату складываются. При группировке по неделям или месяцам берётся последний доступный снимок периода: ежедневные снимки не суммируются в число новых замечаний.

## MPP и XML/XLSX графика {#mpp}

Для 33/34 загрузите `.mpp` в DOCS, выберите его в карточке, выполните импорт и отметьте нужные работы/вехи. Новую версию импортируйте повторно. Наличие файла не гарантирует наличие подходящих данных: проверьте даты, WBS и выбранные работы.

Для 41_mpp задайте параметр отбора и его значения, отчётный день, базовый план начала/окончания и числовой параметр объёма. У выбранных работ должны быть даты именно выбранного базового плана. План распределяется по календарным дням интервала работы, затем формируются значения по отчётным датам. Факт переносится для совпавших дат; при смене состава дат сверяйте его отдельно. Не суммируйте вручную родительские и дочерние работы поверх уже рассчитанного результата.

Для 32 при загрузке XLSX используется **первый лист**, первая строка пропускается как заголовок; далее нужны столбцы WBS, название, начало, окончание, процент выполнения от 0 до 100. Для XML используйте экспорт MS Project с WBS, названием, датами и процентом выполнения. Эти файлы загружаются в форме карточки с компьютера и не являются шаблоном привязки полного блока карточки.
