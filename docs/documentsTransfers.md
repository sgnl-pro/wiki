**Передача** — инструмент для обмена пакетами документации между сторонами с фиксацией состава и версий файлов. В зависимости от настроек типа система может сформировать акт приёма-передачи, запросить подписи отправителя и получателя и разрешить скачивание только после получения пакета.

# Вкладки {.tabset}

## 1. Основные понятия
###### 1. Основные понятия {#main_info}

> **Пакет передачи** — набор зафиксированных версий файлов, объединённых для отправки одному получателю. Пакет имеет номер, шифр, название, тип и статус.

> **Тип передачи** — набор правил, определяющий права пользователей и маршрут пакета: нужен ли акт и его подписание ЭЦП, когда можно скачивать файлы, используется ли публичная ссылка, куда копировать акт и какие значения подставлять при создании.

> **Акт приёма-передачи** — PDF-документ с реквизитами передачи и перечнем файлов. В акте указываются имена, версии, даты создания, размеры и хэш-суммы файлов по алгоритму GOST 2012-256. Если это задано в настройках типа, в конце акта выводится дополнительный текст.

> **Отправитель** формирует пакет, подтверждает или подписывает акт и отправляет пакет получателю.

> **Получатель** принимает или отклоняет пакет. Получателем может быть пользователь проекта, роль проекта или внешнее лицо, которому отправлена публичная ссылка по электронной почте.

> **Статусы передачи**
> 
> Последовательность успешной передачи: `Черновик` → `Сформирован` → `Согласован` или `Подписан` → `Отправлен` → `Просмотрен` → `Получен`
> 
> - <span style="color: #B6BEC7; font-weight: bold">Черновик</span> — пакет создан; состав файлов и свойства можно менять.
> - <span style="color: #F2C94C; font-weight: bold">Сформирован</span> — акт создан и ожидает подтверждения или подписи отправителя.
> - <span style="color: #F2C94C; font-weight: bold">Согласован</span> — отправитель подтвердил пакет без ЭЦП или акт не требуется; пакет можно отправлять.
> - <span style="color: #F2C94C; font-weight: bold">Подписан</span> — отправитель подписал акт ЭЦП; пакет можно отправлять.
> - <span style="color: #FF76E0; font-weight: bold">Отправлен</span> — пакет отправлен выбранному получателю.
> - <span style="color: #0695D7; font-weight: bold">Просмотрен</span> — получатель открыл пакет.
> - <span style="color: #4FCDA6; font-weight: bold">Получен</span> — получатель подтвердил или подписал пакет; файлы доступны по правилам типа передачи.
> - <span style="color: #FF4758; font-weight: bold">Отклонён</span> — получатель отклонил пакет и оставил комментарий. Пакет снова можно отредактировать и сформировать.

## 2. Реестр передач
###### 2. Реестр передач {#registry}

### Вкладки {.tabset}

#### 2.1. Столбцы и навигация
###### 2.1. Столбцы и навигация {#registry_columns}

Откройте вкладку **«Передача»** в верхнем меню DOCS. Каждая строка реестра соответствует одному пакету передачи.

В таблице доступны номер, шифр, название, тип, статус, номер договора, дата создания, автор, отправитель, компания-отправитель, дата отправки, получатель, компания-получатель и дата получения. Отображаемые столбцы зависят от сохранённой настройки таблицы.

Набор, порядок и ширину столбцов можно сохранить как пользовательскую настройку. В реестре также доступны поиск, фильтры, сортировка и постраничный просмотр.

![Вкладка «Передача»](https://lh7-rt.googleusercontent.com/docsz/AD_4nXdBimHypOWwQJDMNl8rkAFULK5wOgqWWCGvdlTRr8rUYI9Yr6m0ExA1fKxzEbzuHCSV7-nZ57fkXwQaAuCn-vrTHHfdYmu44I7zoaDd7IqvHW001J92t2I7r78VQgXiwYg?key=0w72pDhc1Q-bjFjEPHaI_2Sz =50%x)

#### 2.2. Действия с реестром
###### 2.2. Действия с реестром {#registry_actions}

В реестре можно:

- создать пакет;
- открыть пакет нажатием на строку;
- отфильтровать список, в том числе по типам и статусам передачи;
- экспортировать список в XLSX;
- изменить пакет или создать его копию с помощью кнопок при наведении на строку;
- удалить выбранные пакеты;
- открыть корзину и восстановить удалённые пакеты — для администратора проекта.

При копировании в окно создания подставляются тип, шифр, название и все неудалённые файлы исходного пакета. Перед созданием новой передачи параметры и состав файлов можно изменить.

## 3. Карточка пакета
###### 3. Карточка пакета {#transfer_card}

Карточка открывается нажатием на строку реестра. В ней отображаются этапы передачи, сведения о выполненных действиях и таблица зафиксированных версий файлов.

### Вкладки {.tabset}

#### 3.1. Этапы и кнопки действий
###### 3.1. Этапы и кнопки действий {#transfer_actions}

Набор активных кнопок зависит от статуса пакета, настроек типа, роли пользователя и его участия в передаче.

| Действие | Когда доступно | Результат |
|---|---|---|
| **«Добавить»**, **«Удалить»**, **«Обновить версии»** | `Черновик`, `Отклонён` | Изменяется состав или версии файлов пакета |
| **«Сформировать»** | `Черновик`, `Отклонён`; в пакете есть файлы | Создаётся акт или пакет переходит к подтверждению без акта |
| **«Подписать»** / **«Согласовать»** | `Сформирован` | Отправитель подтверждает акт или пакет |
| **«Отправить»** | `Подписан`, `Согласован` | Получателю отправляется ссылка на пакет |
| **«Подписать»** / **«Согласовать»** получателем | `Отправлен`, `Просмотрен` | Пакет переходит в статус `Получен` |
| **«Отклонить»** | `Отправлен`, `Просмотрен` | Пакет возвращается отправителю с комментарием |
| **«Скачать»** | По правилам типа передачи | Скачивается архив файлов и акт, если он формировался |

Наведение на пройденный этап показывает дату и участника действия. Акт можно скачать с этапа подписания, если для типа передачи предусмотрено его формирование.

#### 3.2. Файлы пакета
###### 3.2. Файлы пакета {#files}

В пакет добавляются выбранные версии файлов. В статусах **«Черновик»** и **«Отклонён»** пользователь с соответствующими правами может:

- добавить или удалить файлы;
- обновить выбранные файлы до актуальных версий;
- изменить шифр и название пакета.

Если среди выбранных файлов есть актуальные и неактуальные версии, при обновлении актуальные будут пропущены. После формирования акта состав пакета фиксируется. Если получатель отклонил пакет, состав и свойства снова можно изменить, после чего акт нужно сформировать повторно.

Файлы PDF, офисные документы и поддерживаемые модели можно открыть во встроенном просмотрщике. В ленте просмотра доступны соседние файлы пакета.

## 4. Процесс передачи
###### 4. Процесс передачи {#transfer_process}

### Вкладки {.tabset}

#### 4.1. Создание пакета
###### 4.1. Создание пакета {#creating}

Создать пакет можно несколькими способами:

- на вкладке **«Передача»** — нажать **«Создать»**;
- в разделе **«Документы»** — выбрать файлы и добавить их в новый или существующий пакет;
- из завершённого [комплекта согласования](/docs/reviews#set_card) — создать пакет из выбранных файлов. Шифр и название подставляются автоматически, но их можно изменить; акт можно сформировать сразу.

1. Выберите доступный **«Тип передачи»**.
2. Заполните обязательные поля **«Шифр»** и **«Название»**.
3. При необходимости укажите пользователей и роли в поле **«Оповестить»**.
4. Добавьте файлы. В пакет попадут выбранные на этот момент версии.
5. Если нужно сразу перейти к формированию акта, включите **«Сформировать акт»** и нажмите **«Далее»**. Иначе нажмите **«Создать»** — пакет сохранится как черновик.

#### 4.2. Формирование акта
###### 4.2. Формирование акта {#act}

Чтобы сформировать акт из черновика, откройте пакет и нажмите **«Сформировать»**. Укажите **«Отправителя»**, **«Получателя»**, **«Номер договора»** и **«Название проекта»**.

Администратор может задать эти значения по умолчанию в типе передачи. Если название проекта не задано, подставляется название текущего проекта. Перед формированием акт можно открыть в предпросмотре.

![Параметры акта приёма-передачи](https://lh7-rt.googleusercontent.com/docsz/AD_4nXc5GGcN93VHb2YEmjo-pdeeYj19omPEouhZs3nODQd6YUAViL9rjFGENJRklHy0vhGYjTET4CLapirQUEkMKEj8nfJsMA7o1gbW1Qob-O2lQHBrWaf_VGXNtL9tWTlUI0g?key=0w72pDhc1Q-bjFjEPHaI_2Sz =50%x)

Если для типа акт не требуется, отдельный PDF не создаётся, а пакет сразу переходит к подтверждению и отправке.

#### 4.3. Подтверждение отправителем
###### 4.3. Подтверждение отправителем {#senderSigning}

После формирования акта отправитель выполняет действие, заданное типом передачи:

- если требуется ЭЦП — нажимает **«Подписать»** и выбирает сертификат;
- если ЭЦП не требуется — нажимает **«Согласовать»**.

Для подписания ЭЦП нужны установленный CryptoPro, доступный сертификат и носитель с закрытым ключом, если он хранится на токене.

#### 4.4. Отправка получателю
###### 4.4. Отправка получателю {#sending}

Нажмите **«Отправить»** и выберите получателя. В обычном типе передачи это пользователь или роль проекта. Если в типе включена **«Публичная ссылка»**, укажите адрес электронной почты внешнего получателя.

Получателя можно заранее задать в настройках типа. Перед отправкой его можно изменить.

Система отправит получателю уведомление со ссылкой. Когда получатель откроет пакет, его статус изменится на **«Просмотрен»**.

#### 4.5. Получение и отклонение
###### 4.5. Получение и отклонение {#recipientSigning}

Получатель открывает пакет по ссылке из уведомления, просматривает акт и файлы, а затем:

- подписывает акт ЭЦП, если подпись обязательна;
- нажимает **«Согласовать»**, если ЭЦП не требуется;
- нажимает **«Отклонить»** и указывает комментарий, если пакет нужно вернуть отправителю.

Для публичной передачи учётная запись и доступ к проекту не требуются. Внешний получатель переходит по публичной ссылке, указывает имя и выполняет доступное для типа действие.

![Просмотр пакета получателем](https://lh7-rt.googleusercontent.com/docsz/AD_4nXdWFYqRMl8VzgylrNzBJliU7fzbza-IzZIpHSVXhnwKa5C5uD6STQJlbopekVm7V8mPw0ejZGyoL9vIKAcJarQEZCA5KU7Ir-lGnCh92NejlrzLKUigxN3OFrwcITjCP1E?key=0w72pDhc1Q-bjFjEPHaI_2Sz =70%x)

Если пакет отклонён, отправитель получает уведомление. После исправления состава или свойств пакет можно сформировать и отправить повторно.

#### 4.6. Скачивание
###### 4.6. Скачивание {#downloading}

Нажмите **«Скачать»**, чтобы получить архив с файлами пакета и актом, если он формировался. Возможность скачивания до подтверждения получателем зависит от настройки **«Скачать можно только после подписания»**:

- если настройка включена, скачивание открывается после получения пакета;
- если выключена, файлы доступны раньше пользователям, у которых есть доступ к пакету.

## 5. Настройки типов передачи
###### 5. Настройки типов передачи {#admin}

> Раздел доступен администратору проекта в **«Настройки проекта» → «Передача»**.
{.is-warning}

Администратор управляет типами передачи, доступами ролей и параметрами маршрута. При выборе типа в левой части страницы в правой части отображаются его настройки.

### Вкладки {.tabset}

#### 5.1. Управление типами
###### 5.1. Управление типами {#transfer_types}

Тип передачи можно создать, переименовать, удалить или восстановить. Удалённый тип нельзя выбрать для нового пакета, но созданные ранее передачи сохраняются.

![Настройки типов передачи](/sgnl_docs/transmittal_main.png)

#### 5.2. Права доступа
###### 5.2. Права доступа {#transfer_access}

Доступ к типу передачи определяется ролями пользователя. Права повышаются последовательно: **«Редактирование»** включает создание и просмотр, а **«Создание»** включает просмотр.

| Действие | Просмотр | Создание | Редактирование | Администратор |
|---|:---:|:---:|:---:|:---:|
| Просмотр реестра и пакета | ✓ | ✓ | ✓ | ✓ |
| Создание и копирование пакета | — | ✓ | ✓ | ✓ |
| Добавление, удаление и обновление версий файлов | — | ✓ | ✓ | ✓ |
| Формирование акта | — | ✓ | ✓ | ✓ |
| Изменение типа, шифра и названия | — | — | ✓ | ✓ |
| Удаление пакета | — | — | ✓ | ✓ |

Автор сформированного акта или пользователь с правом редактирования может подтвердить акт и отправить пакет. Получение, подписание и отклонение доступны назначенному получателю. Администратору проекта доступны все типы и административные действия.

#### 5.3. Общие настройки
###### 5.3. Общие настройки {#transfer_general}

- **«Требуется акт приёма-передачи»** — формировать PDF-акт. При выключении также отключаются подписание ЭЦП, ограничение скачивания и публичная ссылка.
- **«Требуется подписание ЭЦП»** — отправитель и получатель подписывают акт сертификатами. Если выключено, стороны подтверждают пакет без ЭЦП.
- **«Скачать можно только после подписания»** — не разрешать получателю скачивать файлы до подтверждения пакета.
- **«Папка для копирования»** — сохранять сформированные акты в выбранной папке DOCS.

#### 5.4. Получатель и значения по умолчанию
###### 5.4. Получатель и значения по умолчанию {#transfer_defaults}

В обычном типе можно выбрать пользователя или роль проекта по умолчанию. При включённой **«Публичной ссылке»** вместо этого указывается внешний email. Поле можно оставить пустым и заполнить при отправке конкретного пакета.

Для нового пакета можно заранее задать список оповещаемых пользователей и ролей. Для акта можно задать отправителя, получателя, номер договора, название проекта и дополнительный текст длиной до 1000 символов. При создании пакета подставленные значения можно изменить.
