#### 2.2. Проекты
###### 2.2. Проекты {#projects}
  
В компании может быть несколько проектов. На вкладке **«Проекты»** теперь показана таблица проектов: в ней можно найти проект, открыть его карточку для редактирования и управлять пользователями в столбце **«Пользователи»**. Статус проекта отображается в таблице; остальные столбцы, включая новые свойства и атрибуты, можно настроить для просмотра.

2.2.1. Перейдите в [_hub.sgnl.pro_](https://hub.sgnl.pro) → **«Организация» → «Проекты»** и нажмите **«Добавить»**.

![добавить_проект.png](/hub/добавить_проект.png)

2.2.2. В карточке проекта укажите обязательные поля: **"Статус"**, **"Название"** и [**"Производственный календарь"**](https://wiki.sgnl.pro/ru/hub/admin#calendar). При необходимости заполните код, часовой пояс, адрес, коммерческое название, описание, даты начала и окончания, стоимость и валюту. Если указана стоимость, выберите валюту; стоимость не может быть отрицательной. Дата окончания не должна быть раньше даты начала. Доступные статусы: **«Ожидание»**, **«В работе»**, **«Финальная стадия»** и **«Завершён»**. Для автоматического добавления новых пользователей компании включите **«Проект по умолчанию для новых пользователей»** и сохраните проект.

Чтобы добавить собственное поле проекта, создайте в [**«Справочниках»**]() атрибут с назначением **«Проект»**. После этого атрибут появится в карточке проекта, а его значение можно вывести отдельным столбцом таблицы.

> Доступно создание проекта на основе ранее созданного проекта (шаблона). Для этого выберите проект для копирования настроек в соответствующем окне.
{.is-info}

![проект.png](/hub/проект.png)

При создании проекта на основе шаблонного будут скопированы:

-   Настройки папочной структуры
-   Настройки прав доступа
-   Атрибуты, назначенные на папки
-   Типы согласований
-   Типы замечаний

Если типы согласований в шаблонном проекте содержат в маршруте пользователей, а не роли, то для того, чтобы эти пользователи участвовали в маршрутах согласования в новом проекте необходимо обязательно соблюдать последовательность:

1.  при создании проекта необходимо указать шаблонный проект для копирования настроек
2.  добавить пользователей в проект
3.  открыть созданный проект в DOCS (в этот момент будут скопированы настройки)


2.2.3. Чтобы назначить пользователей созданному проекту, откройте список в столбце **«Пользователи»** строки проекта. В нём можно добавить пользователя компании или снять уже назначенного.

## 3. Настройки
###### 3. Настройки {#settings}
  
### Вкладки {.tabset}
  
#### 3.1. S3 Сервер {#s3server}
Откройте **«Настройки» → «S3 Сервер»**. Здесь задаются хранилища компании и назначения хранилищ проектам. Для проекта можно выбрать системное хранилище SIGNAL либо подключённое хранилище компании. В таблице назначений выберите проект, хранилище и сервисы, для которых оно будет использоваться, затем сохраните изменения. Если проект должен использовать хранилище компании, сначала добавьте его в настройках компании.

#### 3.2. Календарь {#calendar}
Календарь определяет рабочие и выходные дни организации. Он влияет на расчёт сроков этапов согласования в проекте: выходные дни выбранного календаря не учитываются как рабочие.

3.2.1. Системный календарь соответствует производственному графику Российской Федерации. Чтобы создать календарь организации, откройте **«Настройки» → «Календари»** и нажмите **«Добавить»**.

![chrome_2kfykhc6bc.png](/chrome_2kfykhc6bc.png)

3.2.2. В открывшемся окне укажите название календаря и год, затем отметьте рабочие и выходные дни. Рабочие дни выделены синими кружками. Нажмите **«Сохранить»**.

![chrome_0h5kxpx8ch.png](/chrome_0h5kxpx8ch.png)

Вернитесь в список доступных календарей и активируйте необходимый для работы календарь. Выбранный календарь будет предлагаться по умолчанию при создании новых проектов:

![chrome_kpahusmhux.png](/chrome_kpahusmhux.png)

#### 3.3. Интеграции {#integrations}
В **«Настройки» → «Интеграции»** администратор управляет доступом внешних приложений к API компании. Чтобы добавить интеграцию, нажмите **«Добавить»**, укажите название, выберите необходимые права доступа (`scopes`) и, при необходимости, проекты и срок действия. Если проекты не выбраны, интеграция относится к компании в целом. Сохраните форму и скопируйте показанный секретный ключ в безопасное место: он нужен внешнему приложению для подключения.

В списке интеграций можно открыть сведения об интеграции: `clientId`, права доступа, назначенные проекты и срок действия. Для изменения прав, проектов или срока действия откройте редактирование. Если секретный ключ нужно заменить, используйте **«Обновить секрет»** и передайте новый ключ подключённому приложению. Интеграцию, которая больше не используется, удалите из списка.

#### 3.4. AD и SSO {#adsso}
В **«Настройки» → «AD и SSO»** администратор настраивает корпоративный вход пользователей компании. Нажмите **«Добавить»**, задайте название подключения и выберите тип: **LDAP** для каталога пользователей (в том числе Active Directory) или **OIDC** для единого входа через корпоративного провайдера, если этот вариант доступен в вашей организации. После создания откройте подключение для настройки.

Для **LDAP** укажите адрес и порт сервера, базовый DN, учётную запись чтения и её пароль, атрибут электронной почты. При необходимости настройте защищённое соединение, фильтр поиска, группы и сопоставление имени пользователя. Для **OIDC** укажите `Discovery endpoint`, `Client ID`, `Client secret` и `Scopes` из настроек корпоративного провайдера. Адрес возврата (`Return URL`) можно скопировать из строки подключения и зарегистрировать у провайдера.

В настройках подключения можно указать домены почты пользователей, проекты и приложения по умолчанию, а также включить или отключить подключение. Перед приглашением пользователей проверьте соединение и авторизацию доступными действиями в строке подключения. Пользователям с SSO следует входить через кнопку **«Войти через корпоративную учетную запись (SSO)»**; такое же указание есть в их пригласительном письме.
