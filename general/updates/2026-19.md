**:fire: Доверенности в карточках компаний**

В разделе [«Компании»](/hub/admin#counterparties) появилась вкладка «Доверенности». В карточку компании можно загрузить машиночитаемую доверенность (МЧД), назначить её пользователям и указать проекты, в которых она действует, либо выбрать «Все проекты».

Номер и сроки действия считываются из загруженного файла. В таблице отображаются пользователи, проекты и статус доверенности; список можно отфильтровать по проектам. Доверенности можно скачивать, удалять и восстанавливать из корзины.

**:fire: Сборки моделей в SIGNAL Viewer**

[Сборки BIM-моделей](/docs/viewers#assemblies) теперь можно открывать в SIGNAL Viewer. Несколько моделей отображаются в одной сцене. Для сборки можно выбрать размещение по общим координатам, совмещение центров или внутренних начал, а для каждой модели — задать смещение, поворот и масштаб.

<img src="/release_notes/2026-19-assembly-settings.png" alt="Настройки сборки моделей в SIGNAL Viewer" height="100">

Положение моделей можно менять прямо в просмотрщике и сохранять в сборку. Если для открытия требуется обработать модели, отображается состояние каждой из них; после завершения обработки сборка открывается без перезагрузки страницы. Свойства элементов показываются по группам, с единицами измерения у числовых значений.

<img src="/release_notes/2026-19-assembly-viewer.png" alt="Три модели в одной сборке в SIGNAL Viewer" width="840">

> После обновления модели, обработанные старой версией конвертера SIGNAL, потребуется обработать повторно. При открытии такой модели появится команда «Обновить модель в SIGNAL». Для сборки нужно обновить все входящие в неё устаревшие модели.
{.is-warning}

**:fire: Одна маска именования для нескольких расширений**

В настройках [папки](/docs/settings#masks) имени файла теперь можно назначить сразу нескольким расширениям: например, указать `pdf, dwg, docx` через запятую. Для разных наборов расширений можно задать разные правила, а для одного расширения — несколько допустимых масок имени.

<img src="/release_notes/2026-19-naming-masks.png" alt="Несколько масок для архитектурных решений, конструкций и смет" width="476">

Например, в одной папке можно настроить такие правила. Маска имени задаётся без расширения, а расширения указываются без точки:

| Маска имени | Расширения | Какие файлы разрешены |
| --- | --- | --- |
| `АР-*` | `pdf, dwg` | `АР-План.pdf`, `АР-Фасад.dwg` |
| `КР-*` | `pdf, dwg` | `КР-Фундамент.pdf`, `КР-Перекрытие.dwg` |
| `Смета*` | `xls, xlsx` | `Смета-01.xls`, `Смета-02.xlsx` |
| `*` | `*` | Файлы остальных форматов с любым именем, например `Фото.png` |

Первые два правила позволяют загружать PDF и DWG с разными допустимыми префиксами: `АР-` или `КР-`. Файл `Фото.pdf` не пройдёт проверку: для PDF заданы специальные правила, поэтому общее правило `*` к нему не применяется.

В расширениях также поддерживаются шаблоны: `doc*` подходит для `doc` и `docx`, а `xl?` — для `xls` и `xlt`, но не для `xlsx`. Символ `*` заменяет любое количество символов, `?` — ровно один. Отдельное значение `*` задаёт общее правило для расширений, для которых нет специальных правил.

<img src="/release_notes/2026-19-naming-validation.png" alt="Проверка при загрузке: АР и КР разрешены, Фото.pdf отклонён, Фото.png проходит по общему правилу" width="490">

**:fire: Генерация PDF, согласование и подписание документов из формы**

Из завершённой [формы](/forms/create) можно получить PDF: сначала сгенерировать DOCX по шаблону, при необходимости отредактировать его, затем создать PDF. Оба документа сохраняются в системной папке и доступны из формы для просмотра, скачивания и перехода к файлам.

Сгенерированный PDF открывается в полноценном [просмотрщике DOCS](/docs/viewers#pdf). В нём можно подписать документ ЭЦП или факсимиле, а также создать замечания с графическими пометками на страницах. Действия доступны с учётом прав пользователя и настроек подписания проекта.

<img src="/release_notes/2026-19-generated-pdf-viewer.png" alt="Сгенерированный PDF в просмотрщике DOCS с меню подписания" width="840">

В [настройках типа формы проекта](/forms/settings) можно выбрать тип согласования DOCS. После этого из завершённой формы доступна команда «Создать комплект»: она создаёт черновик согласования с PDF и вложениями этой и связанных форм. Сгенерированный DOCX автоматически в комплект не включается.

Созданный комплект можно открыть, проверить и отправить на согласование и подписание по маршруту выбранного типа согласования DOCS. Для создания нужны соответствующие права; форма при этом остаётся завершённой.

<img src="/release_notes/2026-19-form-documents.png" alt="Завершённая форма с DOCX, PDF и командой «Создать комплект»" width="840">

**:fire: Генерация XML из заполненных форм (MVP)**

В отдельном приложении [**SIGNAL Forms XML**](/forms/generate#xml) можно подготовить XML по данным [заполненных форм](/forms/create). В MVP поддерживаются акты освидетельствования скрытых работ (АОСР), титульный лист и разделы общего журнала работ (ОЖР).

Приложение подключается к проекту через интеграцию SIGNAL и использует значения полей и связи между формами. Типы форм и поля сопоставляются с реквизитами XML; автоматическую привязку можно уточнить вручную. Перед формированием готового пакета выполняется проверка данных и XML по XSD-схемам, отображаются ошибки и предупреждения. Результат выгружается в ZIP-пакет с XML и вложениями.

<img src="/release_notes/forms_xml_1.png" alt="forms_xml_1.png" width="840">

<img src="/release_notes/forms_xml_1.png" alt="forms_xml_2.png" width="840">

<img src="/release_notes/forms_xml_1.png" alt="forms_xml_3.png" width="840">

> Это первая версия инструмента подготовки XML. Для работы нужны настроенные привязки и заполненные исходные данные. Полный ОЖР пока выгружается в черновом режиме: подготовка блоков XML-подписей требует доработки. Подписание УКЭП и передача документов в систему стройнадзора выполняются отдельно.
{.is-warning}

**:sparkles: Доработки функционала**

- В наблюдатели типа формы проекта можно назначать отдельных пользователей вместе с ролями.
- В [шаблонах DOCX](/forms/generate) можно использовать свойства связанных замечаний, согласований и передач: например, шифр и статус комплекта, ответственного за замечание, номер и даты передачи.
- После создания замечания или завершения связанной формы из поля-источника новый объект подставляется в исходное поле, если соответствует его ограничениям. В одиночном поле он заменяет текущее значение без дополнительного подтверждения, а в множественном — добавляется к ранее выбранным значениям. Исходную форму нужно сохранить самостоятельно.

**:sparkles: Новые возможности публичного API**

В [публичном API](/general/api) появились методы для автоматизации работы в DOCS:

| Действие | Метод |
| --- | --- |
| Создать замечание с привязкой к версии файла и графической разметкой PDF | `POST /public/v1/issues/create` |
| Переместить файлы между папками | `PATCH /public/v1/items/move` |
| Создать передачу | `POST /public/v1/documents-transfers/create` |
| Добавить файлы в передачу | `POST /public/v1/documents-transfer-items/add` |
| Прикрепить подготовленный акт к передаче | `POST /public/v1/acceptance-certificates/attach` |
| Отправить передачу адресату | `POST /public/v1/documents-transfer-acceptances/send` |

Для комментария к версии согласования доступны:

- `POST /public/v1/reviews/create` — передать комментарий в поле `comment` при создании комплекта;
- `POST /public/v1/reviews/versions` — получить комментарий в поле `comment` вместе с данными версии;
- `PATCH /public/v1/reviews/comment` — изменить комментарий до запуска, в процессе и после завершения согласования.
