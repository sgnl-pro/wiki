**:fire: Атрибуты в масках для наименований файлов**

В маски наименований теперь можно включать атрибуты файлов с типами `Текст`, `Дата` и `Список`. Такие маски можно использовать наряду с обычными масками без атрибутов. Для настройки маски с атрибутами нажмите на карандаш:

![2026.15_-_настройка_маски.png](/release_notes/2026.15_-_настройка_маски.png =1200x)

При загрузке, перемещении, копировании или переименовании файла система запрашивает значения атрибутов, формирует имя и одновременно сохраняет атрибуты. Система автоматически определяет атрибуты, если они уже заложены в имя исходного файла. В окне загрузки можно массово задавать значения атрибутов, которые есть у нескольких файлов. Значения атрибутов влияют на имя файла и наоборот:

![2026.15_-_переименование_файлов.png](/release_notes/2026.15_-_переименование_файлов.png =1200x)

**:fire: Связь полей форм с элементами HUB и DOCS**

Ранее формы можно было связывать только друг с другом и файлами из DOCS. Реализовали новые типы полей, в качестве значений которых выступают:
- элементы проекта DOCS (`Замечания`, `Комплекты согласования`, `Передача`)
- справочники HUB (`Виды работ`, `Материалы`, `НТД`)
- `Контрагенты` и `Пользователи`

![2026.15_-_новые_источники.png](/release_notes/2026.15_-_новые_источники.png =1200x)

Уже сейчас новые поля можно использовать для ведения цифрового документооборота, а в следующих релизах появится возможность применять их в шаблонах для генерации DOCX. В частности, это позволит отказаться от форм "Виды работ", "Материалы" и "НТД" на уровне проекта, заменив их на справочники на уровне компании, а также применять комплекты согласования вместо формы "Проектная документация".

**:fire: Экспорт и импорт форм из XLSX**

Экспортировать в качестве строк таблицы можно все записи из реестра форм одного типа, либо только только выбранные записи. В качестве столбцов — все поля формы, либо только отображаемые в реестре. Для экспорта доступны поля всех типов. Помимо полей экспортируются также системные свойства формы (номер, тип, статус, кто когда создал и отредактировал) и её текущего этапа:

![2026.15_-_экспорт_форм.png](/release_notes/2026.15_-_экспорт_форм.png =1200x)

Для импорта доступны только поля с типами `Строка`, `Число`, `Да/Нет`, `Дата и время`, `Диапазон дат` и `Список вариантов`. Перед импортом можно скачать шаблон XLSX с доступными полями формы данного типа. Остальные столбцы при импорте игнорируются, т.е. их можно оставить в файле (например после экспорта такого файла из другого проекта). Недопустимые значения полей подсвечиваются красным, такие записи не будут импортированы.

Перед импортом также можно поставить галочку "Завершить импортируемые формы, если возможно" — тогда формы, у которых корректно заполнены все обязательные поля и отсутствуют этапы, сразу будут созданы в статусе `Завершена`. Остальные формы будут созданы в статусе `Черновик`.

Для импорта у пользователя должны быть права на создание форм данного типа.

![2026.15_-_импорт_форм.png](/release_notes/2026.15_-_импорт_форм.png =1200x)

**:fire: Расширенный синтаксис шаблонов для генерации DOCX**

Ранее в шаблонах можно было только вставлять значения полей в фигурных скобках — например `{{date}}` или `{{customer.name}}`. Теперь шаблоны стали гораздо умнее и гибче. Вот что мы добавили:

- **Условный вывод** — можно показывать или скрывать целые блоки текста в зависимости от того, заполнено ли поле. Например, выводить строку «ОГРН …» только если этот реквизит указан.

- **Циклы по спискам** — если у вас несколько однотипных элементов (например, вложения, виды работ, этапы), вы можете автоматически перебрать их все и вставить в документ с полями в нужном порядке. При этом можно ставить запятые, нумерацию и форматирование между элементами.

- **Вычисления и логика** — Вы можете использовать простые математические операции (сложение, умножение), сравнения (больше, меньше) и даже тернарные условия («если — то — иначе») прямо внутри документа.

- **Вставка изображений** — изображения из вложений автоматически подставляются в документ в нужном месте. Если картинки нет — блок просто пропускается.

- **Кликабельные ссылки** — можно сделать любой текст или название файла активной ссылкой, по которой можно перейти в систему или скачать файл.

- **Работа с датами и авторами** — в документ можно подставить не только поля формы, но и системные данные: номер формы, дату создания, дату изменения, автора и редактора (с полным или кратким именем), а также данные по этапам согласования — кто ответственный, кто завершил, когда и с каким комментарием. Также доступна вставка текущей даты и времени генерации документа.

- **Более понятные ошибки** — если в шаблоне допущена ошибка, система укажет конкретное место и объяснит, что не так.

Всё это позволяет создавать документы, которые автоматически подстраиваются под данные, экономя время на ручных правках. Полное описание синтаксиса с примерами доступно [здесь](/forms/generate).

:sparkles: В [публичный API](/general/api) добавили методы:
- `PATCH /public/v1/projects` (изменение информации о проекте)
- `POST /public/v1/attributes/types/create`, `PATCH /public/v1/attributes/types` (добавление и изменение атрибутов проекта)
- `POST /public/v1/attributes/types/list/items/create`, `PATCH /public/v1/attributes/types/list/items` (добавление и изменение значений списочных атрибутов проекта)
- `DELETE /public/v1/permissions/{permissionId:guid}` (удаление прав на папки)
- `GET /public/v1/reviews/types/names` (получение списка типов согласования проекта)
- `POST /public/v1/reviews/create` (создание комплекта согласования)
- `PATCH /public/v1/reviews/type` (изменение типа у комплекта согласования)
- `POST /public/v1/reviews/items/add`, `POST /public/v1/reviews/items/remove` (добавление и удаление файлов из комплекта согласования)
- `POST /public/v1/reviews/process/start` (запуск процесса согласования)
