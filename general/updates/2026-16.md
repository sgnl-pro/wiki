**:fire: Уведомления в MAX и Telegram**

В [профиле пользователя](/hub/user#notifications) можно выбрать получение уведомлений SIGNAL не только по электронной почте, но и в мессенджерах **MAX** и **Telegram**. Ранее уведомления HUB приходили только на email. Настройка в общих параметрах уведомлений применяется и к отдельным разделам по умолчанию; при необходимости правила для конкретных событий можно изменить.

**:sparkles: Справочники материалов, НТД и видов работ**

Увеличили максимальную длину названия в справочниках [видов работ, материалов и НТД](/hub/admin) до **1080 символов**. Для поля `Код` установили ограничение — **до 255 символов**. Это позволит загружать и хранить записи с развёрнутыми наименованиями, которые раньше не помещались в поле.

**:sparkles: Доработки функционала**

- В [настройках компании](/hub/admin#settings) можно назначить проекту системное S3-хранилище.
- На странице [SIGNAL Tools](/tools) добавили сборки **SIGNAL Basic for Revit** и **SIGNAL Basic for Navisworks** для скачивания по прямой ссылке.

**:fire: Копирование папок вместе с файлами и версиями**

При [копировании структуры папок](/docs/folders#structure_tree) теперь можно выбрать один из двух вариантов: скопировать только папки или папки **вместе с файлами и всей историей их версий**. Раньше структуру папок и файлы приходилось копировать отдельными действиями.

Копирование доступно внутри проекта, между проектами и между компаниями, если используется одно S3-хранилище. Это позволяет переносить типовую структуру сразу с рабочими документами, не теряя предыдущие версии файлов.

**:sparkles: SIGNAL Viewer — удобнее на мобильных устройствах**

Доработали [SIGNAL Viewer](/docs/viewers#bim):

- окно свойств выбранного элемента можно растягивать, чтобы просматривать длинные названия и значения без лишней прокрутки;
- в мобильной версии снова открывается дерево модели;
- измерения корректно размещаются на экране и снова можно ставить точки для измерения расстояния;
- окно настроек остаётся доступным при повороте устройства;
- для мобильных устройств установили более удобную скорость обзора модели по умолчанию.

Таким образом, основные инструменты просмотра — дерево модели, свойства, измерения и настройки — стали доступны и удобнее при работе со смартфона или планшета.

**:sparkles: Доработки функционала**

- В списке файлов по наведению на значок обработки теперь отображаются статус, дата и время конвертации отдельно для **Tangl Viewer**, **Autodesk Forge** и **SIGNAL Viewer**. Значок показывает наиболее успешный результат обработки. Ранее было невозможно быстро понять, в каком именно просмотрщике файл готов к открытию.
- В [Collabora](/docs/collabora) доработали сравнение версий документов.
- При входе в проект пользователи сразу видят актуальные права доступа: ранее после изменения роли или доступа иногда требовалось очистить кэш браузера.
- В уведомления о замечаниях комплекта больше не попадают файлы, которых нет в этом комплекте.
- В диалоге загрузки файлов уведомление содержит ссылку на папку, в которую загружены файлы.
- Можно импортировать и экспортировать пустые папки без добавления служебного TXT-файла.

**:hammer_and_wrench: Исправление ошибок**

- Восстановили загрузку файлов во вложениях замечаний, при [генерации документов](/forms/generate) и добавлении [ручной подписи](/docs/folders#faximile).
- При скачивании файла с несколькими присоединёнными ЭЦП в `.sig` сохраняются подписи всех подписантов. Ранее в выгруженном файле могла остаться только первая подпись.
- Исправили сохранение XLSX при работе в Collabora.
- Исправили центрирование страницы при перелистывании PDF.
- Отключили отправку уведомлений по удалённым замечаниям.

**:fire: Создание связанной формы из поля-источника**

При [заполнении формы](/forms/create#3-заполнение-полей) пользователь может создать новую связанную форму прямо из поля-источника. Если у него есть право создавать формы требуемого типа, в раскрытом списке появляется кнопка `Добавить`. Она открывает панель создания формы; после заполнения новую форму можно выбрать в исходном поле.

Раньше для этого нужно было отдельно перейти в реестр нужного типа, создать форму, завершить её и затем вернуться к исходной форме. Теперь весь сценарий выполняется без выхода из текущей карточки.

**:sparkles: Поля-источники и реестры форм**

- В [конструкторе форм](/forms/builder) для одного поля-источника можно указать только один тип форм. Это исключает неоднозначность при выборе значения и упрощает настройку связанных форм.
- В реестре скрывается столбец, если соответствующее поле недоступно пользователю во всех типах форм проекта. Ранее такой пустой для пользователя столбец мог отображаться в таблице.
- Исправили выравнивание названий типов форм в дереве.

**:fire: Публичный API FORMS**

В [публичном API](/general/api) доступны методы для:

- чтения типов форм, групп, полей и этапов;
- поиска и получения заполненных форм;
- создания, изменения и завершения форм.

Через API не предоставляются операции управления правами, маршрутами согласования, удалением и восстановлением форм. Это позволяет интеграциям передавать и получать данные форм, сохраняя управление доступом и согласованием внутри SIGNAL.
