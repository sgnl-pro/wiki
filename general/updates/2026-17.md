**:fire: Новые поля проекта и переработка таблицы проектов**

Вкладка [Проекты](/hub/admin#projects) теперь содержит таблицу с проектами, а не пользователями. Редактирование пользователей проекта доступно в соответствующем столбце: можно отобразить выпадающий список текущих пользователей для снятия с проекта или открыть полноценное окно редактирования для добавления пользователей в проект.

Проектам добавили дополнительные свойства:
- `Статус` ("Ожидание", "В работе", "Финальная стадия", "Завершён")
- `Коммерческое название`
- `Описание`
- `Начало и Окончание`
- `Стоимость` и `Валюта`

Также можно назначать проектам атрибуты компании, ими можно управлять в разделе **Справочники.**

:hammer_and_wrench: Исправили ошибку дублирования некоторых пользователей в таблице при переключении страниц.

**:fire: Скиллы и инструкции проекта для ИИ-ассистента**

Реализовали системные и пользовательские скиллы, а также инструкции проекта для ИИ-ассистента.

1. **Скилл** — это готовый сценарий работы ассистента: оформить замечание, разобрать папку, найти ответ в справке, навести порядок в именах файлов и т.д. Скиллами можно пользоваться двумя способами — или просто попросить словами, или вызвать командой.

2. **Инстуркции** позволяют научить ИИ-ассистента правилам вашего проекта — терминологии, соглашениям по структуре папок и именованию файлов, тому, что важно именно у вас. Ассистент будет учитывать эти правила в каждом ответе и действии.

Скиллы и инструкции настраиваются администратором проекта в корневой папке `.DOCS-AGENT`. Подробное описание функционала см. в [статье](/docs/ai).

**:fire: Пакетное обновление версий выбранных файлов**

Реализовали пакетное [обновление версий файлов](https://wiki.sgnl.pro/r/docs/folders#versions): выделите нужные файлы в DOCS, вызовите контекстное меню правой кнопкой мыши и выберите команду `Загрузить версию`. Выберите на устройстве нужное количество файлов и сопоставьте их с файлами из DOCS в специальном окне. Файлы с одинаковыми именами сопоставятся автоматически, но это сопоставление можно изменить. Также можно добавлять и удалять файлы из списка сопоставления как со стороны DOCS, так и со стороны устройства. Если файл в DOCS окажется занят на редактирование, то система не даст его обновить.

**:sparkles: Доработки функционала**
- Добавили поддержку ссылок на файлы, которые были перемещены: теперь пользователь при наличии доступа к папке может перейти по старой ссылке и открыть файл.
- Доработали редактор [графика Ганта](/docs/viewers#mpp):
	- реализовали полноценную клавиатурную навигацию;
  - доработали логику связи полей с календарём;
  - значительно улучшили интерфейс редактирования.
- Доработали сечения в [SIGNAL Viewer](/docs/viewers#signal-viewer-new):
	- появился режим «Сечение по грани»: после включения указатель становится перекрестием, а клик по поверхности модели ставит плоскость сечения параллельно этой поверхности через точку клика и убирает половину модели, обращённую к камере;
  - клавиша Escape теперь выходит ровно из того режима, в котором находится пользователь: сначала закрывается активный инструмент, затем снимается сечение (выбор элементов сохраняется), и только следующее нажатие снимает выбор;
  - исправлено ложное состояние кнопки — после выхода из режима «Сечение по грани» и повторного нажатия кнопка больше не показывает «Скрыть сечение» при пустом экране, а снова запрашивает клик по поверхности;
  - ускорена отрисовка среза, а скрытие и изолирование элементов при включённом сечении больше не заставляет пересчитывать срез всей модели.
- Стали передавать при обработке [Tangl](/docs/viewers#tangl-viewer) существующие имена моделей, чтобы отображать их в tangl вместо guid. При этом переименование модели в DOCS не повлечёт автоматическое переименование в tangl, а повторная отправка версии модели сейчас не поддерживается. Поэтому в случае переименования модели нужно загрузить новую версию и отправить её в обработку.
  
:hammer_and_wrench: Исправили ошибку, при которой ломалось завершение стадии [согласования](/docs/reviews) при копировании файла с двумя атрибутами одного типа.

**:fire: Значения по умолчанию для полей форм в проекте**

Реализовали редактирование значений полей у типов форм в [настройках проекта](/forms/settings). Эти значения будут использоваться по умолчанию при [создании экземпляров форм](/forms/create). Задавать значения можно для любых типов полей, в том числе для связанных форм (например удобно для автоматической подстановки сведений об объекте строительства в акты) и других типов источников.

![2026-17-значения_по_умолчанию.png](/release_notes/2026-17-значения_по_умолчанию.png =1200x)

![2026-17-создание_замечания_из_формы.png](/release_notes/2026-17-создание_замечания_из_формы.png =1200x)
- Добавили [настройку](/forms/builder) для обеспечения уникальных значений в рамках проекта поляей с множественным выбором по частичному совпадению вариантов (например можно настроить, чтобы одна запись журнала не могла применяться в двух разных актах определённого типа):

- Добавили предупреждение при выходе из формы при изменении ответственного и плановой даты без сохранения.
- Добавили поддержку настройки уникальных значений связанных форм в [синтаксис генерации DOCX](/forms/generate) (например можно настроить в шаблоне акта, чтобы повторяющиеся материалы или работы из разных записей журнала не перечислялись несколько раз).
